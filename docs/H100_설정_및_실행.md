# H100 설정 및 실행 (Pull 후 한 번에)

Pull 받은 뒤 **환경 설정 한 번** → **실행 스크립트 한 번**으로 끝나게 정리했습니다.

---

## 1. 저장소 받기

```bash
cd ~/CY
git clone https://github.com/CY-H1329/Spatial_MAS.git
cd Spatial_MAS
```

이후 최신 받을 때:

```bash
cd ~/CY/Spatial_MAS
git pull origin main
```

---

## 2. 환경 설정 (최초 1회)

### 방법 A: 빠른 설치 (Conda 없이, base 그대로)

Conda 해결이 오래 걸리면 **pip만** 쓰는 편이 훨씬 빠릅니다. `(base)` 에서:

```bash
cd ~/CY/Spatial_MAS
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu121
pip install -r requirements-fast.txt
```

끝나면 그대로 `python run_eval.py ...` 실행하면 됩니다. (conda activate 불필요)

### 방법 B: Conda 환경 쓰기

```bash
cd ~/CY/Spatial_MAS
bash scripts/setup_h100.sh
```

(또는 `conda env create -f environment.yml` 후 `conda activate spatial_mas`)

이 스크립트가 하는 일:

- Conda 환경 `spatial_mas` 생성 (없을 때만)
- PyTorch가 GPU를 못 잡으면 CUDA 12.1용 PyTorch 추가 설치
- `.env` 없으면 API 키 설정 안내

### Datasets: téléchargement une fois (4 benchmarks)

Avant les runs MAS, téléchargez les benchmarks une fois :

```bash
cd ~/CY/Spatial_MAS
python scripts/setup_datasets.py
```

Ou : `bash scripts/run_h100_setup_datasets.sh`

Les datasets (STVQA-7K, OMNI3D-BENCH, CV-Bench, 3DSRBench) sont mis en cache dans `~/.cache/huggingface/datasets/` et réutilisés automatiquement ensuite.

---

### 방법 C: 기존 Conda 환경 확인 후 그 환경에서 실행

서버에 이미 있는 Conda 환경을 쓰고 싶을 때:

**1) 환경 목록 확인**
```bash
cd ~/CY/Spatial_MAS
conda env list
```

**2) 필수 패키지 확인 (스크립트 사용, 선택)**
```bash
bash scripts/check_env.sh
```
→ 현재 환경에 torch, transformers, datasets, openai 등 있는지 보고, 없으면 설치 명령을 안내함.

**특정 환경만 확인**
```bash
bash scripts/check_env.sh 내환경이름
```

**3) 쓸 환경 활성화 후 부족한 것만 설치**
```bash
conda activate 원하는환경이름
# 부족하면 (스크립트가 안내한 대로):
pip install transformers datasets huggingface_hub accelerate qwen-vl-utils pillow openai tqdm pyyaml pandas numpy
```

**4) 실행**
```bash
cd ~/CY/Spatial_MAS
python run_eval.py --models qwen llava gpt --split val
```

스크립트 없이 수동으로 확인하려면:
```bash
conda activate 어떤환경
python -c "import torch, transformers, datasets; print('OK')"
```
→ 에러 없으면 그 환경에서 그대로 실행하면 됨.

## 3. API 키 설정 (GPT 쓸 때만)

GPT 평가를 쓰려면 OpenAI API 키가 필요합니다. **한 번만** 설정하면 됩니다.

**방법 A: .env 파일 (추천)**

```bash
cd ~/CY/Spatial_MAS
cp .env.example .env
# .env 를 열어서 OPENAI_API_KEY=sk-... 실제 키로 수정
nano .env
```

또는 한 줄로:

```bash
echo 'export OPENAI_API_KEY=sk-여기에본인키' > ~/CY/Spatial_MAS/.env
```

**방법 B: 매번 터미널에서**

```bash
export OPENAI_API_KEY=sk-여기에본인키
```

`.env`에 넣어 두면 `run_h100.sh`가 자동으로 불러옵니다.  
`.env`는 Git에 올라가지 않습니다 (`.gitignore`에 있음).

---

## 4. 실행 (평가 + 실패 분석 + 틀린 샘플 저장)

```bash
cd ~/CY/Spatial_MAS
bash scripts/run_h100.sh
```

이 스크립트가 하는 일:

1. `.env`가 있으면 로드 (OPENAI_API_KEY 등)
2. Conda `spatial_mas` 활성화
3. `run_eval.py` 실행 (Qwen + LLaVA + GPT, val 스플릿)
4. 방금 생긴 `results/날짜시간/` 에 대해 `analyze_failures.py` 실행
5. 같은 run에 대해 `export_failed_samples.py` 실행

**빠른 테스트 (일부만):**

```bash
bash scripts/run_h100.sh --max_samples 50
```

**GPU 지정:**

스크립트 안에서 수정하거나, 실행 전에:

```bash
export CUDA_VISIBLE_DEVICES=0
bash scripts/run_h100.sh
```

## 6. 단일 + 멀티 통합 실험 (H100, 한 프로그램에서 순차 실행)

한 번 실행하면 **단일 에이전트 → 멀티(3 agents 다수결)** 순차 실행 후, **정확도 비교**와 **서로 틀린 문제 비교**까지 한꺼번에 정리됩니다.

**실행 (기본: train, max_per_category 100):**

```bash
cd ~/CY/Spatial_MAS
git pull origin main
bash scripts/run_h100_multiagent.sh
```

**Conda 환경이 다르면** (예: `spatialeval_orchestration`):

```bash
CONDA_ENV=spatialeval_orchestration bash scripts/run_h100_multiagent.sh
```

**빠른 테스트 (샘플 줄이기):**

```bash
bash scripts/run_h100_multiagent.sh --max_per_category 50
```

결과는 `results/YYYYMMDD_HHMMSS_unified/` 아래에 쌓입니다.

- **단일**: `qwen_results.json`, `llava_results.json`, `qwen_preds.jsonl`, `llava_preds.jsonl`
- **멀티**: `qwen_multiagent_preds.jsonl`, `llava_multiagent_preds.jsonl`, `conversations/` (질문 + Agent1/2/3 답 + 다수결 + GT)
- **정확도 비교**: `comparison_single_vs_multi.txt`, `.csv`, `.json`
- **틀린 문제 비교**: `wrong_comparison.txt`, `.csv`, `.json`
  - `both_wrong`: 단일·멀티 둘 다 틀린 문제
  - `only_single_wrong`: 단일만 틀림 → 멀티는 맞음 (다수결로 회복)
  - `only_multi_wrong`: 단일은 맞음 → 멀티만 틀림 (악화)

## 7. Qwen vs LLaVA vs Qwen+LLaVA 협력 (2 agents)

Qwen 단일, LLaVA 단일, **Qwen+LLaVA 협력**(같은 문제에 각자 답 → 일치하면 그 답, 불일치면 한쪽으로 tie-break) 성능 비교.

**실행:**

```bash
cd ~/CY/Spatial_MAS
git pull origin main
bash scripts/run_h100_collab.sh
```

**옵션:** `--max_per_category 7` (기본), `--tie_break llava` (불일치 시 LLaVA 답 사용, 기본은 qwen)

결과: `results/YYYYMMDD_HHMMSS_collab/`  
- `comparison_collab.txt`, `.csv`: qwen_only / llava_only / qwen_llava_collab 정확도  
- `collab_qwen_llava_preds.jsonl`: 샘플별 qwen_pred, llava_pred, collab_pred, agree 여부
